# 遥测系统

## 简介

ArkPets 内置了一套可自愿退出的遥测系统，用于收集程序在真实环境中的运行情况，以帮助开发者了解：

- **崩溃情况**：软件是否频繁发生崩溃，以及崩溃的具体原因；
- **性能表现**：桌宠在不同设备上渲染的流畅程度；
- **使用偏好**：哪些功能或设置项更受用户欢迎。

这些数据是改进软件稳定性和体验的重要依据。遥测功能默认的开启的，但您可以随时在「设置」页面中找到「上传匿名使用数据」选项并关闭它。

## 隐私声明

### 采集范围

我们十分重视隐私保护，并尽力将采集范围限制在最小限度：

- **不会采集**您的个人信息、个人文件内容、剪贴板、屏幕画面或浏览记录；
- **不会采集**敏感配置项，例如 Mirror 酱 CDK 密钥等；
- **不会自动上传**日志文件，仅在您主动点击「上传日志」时才作为反馈发送。

### 数据安全

我们将最大程度地采取业内最成熟的技术保证您的数据安全：

- 所有数据均为**匿名统计**，无法关联到您的个人身份，只有网络传输环节会需要用到 IP 地址等必要的网络信息；
- 所有数据均要求 TLS **安全传输**，这意味着中间人攻击无法解密这些数据；
- 所有数据经由 [Sentry](https://sentry.io) 平台托管处理，这是一个著名的第三方错误监控服务平台，在全世界范围内被广泛使用，具有成熟的数据安全保护技术。

### 数据共享

只有 ArkPets 团队及 Sentry 服务器有权存储所有数据，并且承诺**不会共享给任何第三方**。

### 允许自愿退出

您可以随时在设置中关闭「上传匿名使用数据」。关闭后，程序将立即停止上报，并清除本机中所有尚未上报的数据。

如果您发现任何超出上述范围的数据被采集，或者您要求审查您所上报的数据，欢迎提交 Issue 向我们反馈。

## 遥测内容

所有自动上报的事件分为以下几类：

|            事件             | 触发条件           | 上报内容                             |
|:-------------------------:|----------------|----------------------------------|
|  模型会话<br>(MODEL_SESSION)  | 桌宠每次退出时        | 使用的模型、本次运行时长；是正常退出、异常退出还是因崩溃结束运行 |
| 桌面会话<br>(DESKTOP_SESSION) | 启动器每次退出时       | 本次启动器运行时长                        |
|     配置快照<br>(CONFIG)      | 桌宠启动时          | 当时的各项设置值（排除敏感信息）                 |
|   系统信息<br>(SYSTEM_INFO)   | 桌宠 GL 上下文初始化后  | 系统的显卡供应商、驱动版本号、操作系统名称与架构         |
|           性能指标            | 桌宠运行期间每若干秒采集一次 | 渲染耗时、渲染分辨率、帧率、内存占用、CPU 占用        |
|           崩溃报告            | 桌宠崩溃时          | 异常类型和调用堆栈                        |

此外，当启动器出现错误对话框时，您可以手动点击「上传日志」按钮，将程序的日志文件作为反馈发送给我们。

## 技术细节

以下内容面向本项目的开发者以及技术型用户。

### 架构

ArkPets 由两个独立 JVM 进程构成：**Desktop**（JavaFX 启动器）与 **Core**（libGDX 桌宠渲染）。Core 可以脱离 Desktop 单独运行。遥测架构的核心约束是：**只有 Desktop 与 Sentry 通信，Core 不具备通信功能**。

跨进程回传以文件系统为媒介，采用 **WAL（Write-Ahead Log）** 机制：

- WAL 文件位于日志目录，文件名包含 PID 信息，后缀为 `.wal`，采用顺序追加写入；
- 帧格式为 `magic("WAL1") | version | type | seq | timestamp | payloadLen | payload | crc32(payload)`，读取时丢弃破损写入（torn write）和校验失败的尾部记录；
- Desktop 在启动时和退出时各扫描一次 WAL，仅当对应进程已死亡（判定为无主）才消费，上传成功后删除文件（删除即提交）。

会话生命周期采用**心跳**方案，而非仅在退出时写记录，从而规避断电和杀进程场景下的数据丢失：进程启动即写首条心跳，此后守护线程每若干秒追加一条。消费端按 WAL 内容判定三种结束态：

|  结束方式  | Sentry 级别 | WAL 内容特征              |
|:------:|:---------:|-----------------------|
|  正常退出  |   INFO    | 末条心跳为 `stopped=true`  |
| 可捕获的崩溃 |   ERROR   | 含 `exception` 记录及异常堆栈 |
| 断电或杀进程 |   WARN    | 仅含 `running` 心跳       |

其他关键设计：

- **时间戳语义**：WAL 帧头的时间戳会被写入 Sentry 事件 / Metrics，保证代表事件发生时刻而非上报时刻；
- **配置快照**：Core 启动时经反射一次性采集 `ArkConfig` 公有标量字段为独立 WAL 记录，携带会话发生时的配置而非上报时的值；
- **性能采样**：Core 在渲染回调内仅做内存聚合，快照随心跳事件搭车落盘，渲染线程永不执行 I/O。

### 配置

#### Sentry 数据源名称（DSN）

- **Gradle 任务**：Gradle 项目属性 `SENTRY_DSN` 是唯一来源，定义于 `desktop/build.gradle`（缺失时回退到占位黑洞 DSN）：
  - `run` / `debug` 系列任务会通过 `jvmArgs` 注入 `-Dsentry.dsn=...`；
  - `dist` 系列任务会通过 jpackage `--java-options` 将 DSN 固化进发行版启动配置。

- **CI 构建**：由 `.github/workflows/build.yml` 通过 `ORG_GRADLE_PROJECT_SENTRY_DSN: ${{ secrets.SENTRY_DSN }}` 提供密钥。

- **其他情景**：如果不是在以上两类情景中运行的程序（例如直接使用 IDEA 运行了入口点），您还可以通过以下三种方式手动配置（优先级从高到低）：
  1. Java 系统属性 `-Dsentry.dsn`；
  2. 环境变量 `SENTRY_DSN`；
  3. `sentry.properties` 文件。

#### Sentry 环境标识（environment）

代码中的默认值为 `"dev"`；构建发行版由 `-Dsentry.environment=production` 覆盖为生产环境；
